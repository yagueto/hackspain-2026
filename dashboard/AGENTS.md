# Dashboard

- Angular 22 standalone components with signals and lazy-loaded routes. Run commands from `dashboard/`.
- The existing development server is `ng serve` at `http://localhost:4200/`. Preserve that server and port; do not start a second instance unnecessarily.
- Verify with `npm run build`, `npm test -- --watch=false`, and `npm exec --no -- prettier --check "src/**/*.{ts,html,css}"`.
- UI text is Spanish. Keep feature templates and styles separate and use the shared icon component.
- `Home.addresses` is the string-array signal for incoming addresses. `OperationalMap` accepts `addresses` and optional coordinate-bearing `locations`. Known coordinates avoid geocoding requests.
- Leaflet uses its ESM distribution, with types re-exported in `src/leaflet.d.ts`. Tiles are provided by OpenStreetMap and must retain attribution.
- The public Nominatim endpoint is only for this low-volume, single-user demo: one request at a time, at least 1100 ms between starts, no polling or autocomplete, and session caching. Never send confidential addresses. Policy: https://operations.osmfoundation.org/policies/nominatim/ .
- Before multi-user production, move geocoding to a backend with application-wide rate limiting/caching or a suitable hosted/self-managed provider. The endpoint is configurable through the `geocoding-endpoint` meta tag in the served index and the `GEOCODING_ENDPOINT` injection token; replacement endpoints must return Nominatim-compatible results.
- Demo locations and communications are simulated, not real operational data. Future sections remain disabled until their routes and screens are implemented.
- Shared pagination uses `PaginatedList` with `ResizeObserver` and each list's `--page-row-height`; card heights must use the same variable. Reserve space for the pager even on a single page to avoid resize loops. The one-column breakpoint is 800px, with five items per page and fixed panel heights on mobile.
- The dashboard starts without an incident or resource selection. Keep the single demo indicator in the topbar; do not repeat demo disclaimers throughout the panels.
- Unit map locations can have an optional `route` with `status: 'active' | 'completed'`, destination coordinates, an optional destination label and optional intermediate `via` points. Only active routes are queried and drawn. The UI estimates remaining road travel, not historical GPS tracks or live traffic.
- Routing uses an OSRM-compatible endpoint configured by the `routing-endpoint` meta tag / `ROUTING_ENDPOINT` token. The public demo server is for reasonable non-commercial usage only: requests are serialized at 1100 ms intervals, cached for five minutes and never polled. Use a suitable hosted or self-managed backend before production or confidential location data. Policy: https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server .
- Leaflet route rendering is isolated in `resource-route-layer.ts`; route labels use the distance-based midpoint of the road geometry. Keep marker/popup text DOM-created with `textContent`, and respect `prefers-reduced-motion` for incident pulses.
- `/incidencias` is isolated in `features/incidents/` and shares `OperationalMap` with Home. Its list scrolls rather than paginating, and the detail map receives only the selected incident and its associated units.
- Prefer larger operational values over redundant subtitles and field captions. Keep semantic labels with `sr-only` or accessible names, show the filtered incident count only in its heading, and retain map attribution, error notices and the demo indicator. Home's mobile panel heights must accommodate five enlarged rows plus filters and pagination.
- `IncidentStore` starts with the shared operation mocks plus feature-local supplemental details. Provide `INCIDENT_UPDATES` with an `Observable<IncidentUpdate>` to connect a future SSE/WebSocket adapter; the default is `EMPTY`, not a live connection. Updates patch an existing incident, replace that incident's unit snapshot when `units` is supplied, and upsert timestamped timeline events by incident/event ID. Keep transport parsing, validation and reconnection in the adapter.
- During the hackathon, prioritize implementation plus a build and brief smoke check. Defer full test suites and exhaustive visual verification unless requested.
- `DemoRouteSimulation` starts at application initialization, advances active mock journeys at 10x speed using their calculated geometry, and keeps progress across map instances and navigation. No position polling or routing calls occur on simulation ticks. Reloading recreates the session. Optional `route.navigation` supplies the current remaining geometry/time to the map without another routing request.
- The shared mocks start with two ongoing rescues (INC-004 and INC-008), 10 units (exactly three fire crews) and two extra `kind: 'place'` markers that are not counted as resources. M progressively adds INC-001 (fire), INC-002 (power failure) and INC-003 (second fire). Keep incremental marker/polyline updates to avoid restarting incident pulses or recentering the map on every simulation tick.
- `/recursos` reuses the Incidencias layout styles, `IncidentStore` units and `DemoRouteSimulation.project` for current status/position. Resource profiles are supplemental mocks in `features/resources/resources.mock.ts`; prior interventions are recorded in IncidentStore when a unit is reassigned. Pass stable source locations to the shared map, not a fresh projected array on every simulation tick.
- Direct selection links use `/recursos?recurso=B-03` and `/incidencias?incidencia=INC-001`. Current assignments and resource history link to the latter. Focused navigation/filter smoke checks: `npm test -- --watch=false --include="src/app/features/resources/resources.spec.ts"`.
- Home uses `IncidentStore` for incidents and stable source units. `OperationLogStore` shares that store's history and owns questions/drafts; it is initialized before the route simulation. Route arrivals append one event, not a stream of position updates.
- The Home log is a third column at 1200px and above and a modal overlay below that width. Keep it outside `.dashboard-grid` so `SplitPane` still manages only the map and operation lists. There is no general message composer.
- M advances the three-step demo from any route, ignoring repeated/composing/modified keys and text editing. Step 1 dispatches B-03 and A-01; step 2 opens the existing human-decision panel for backup power versus main-transformer repair; step 3 transfers B-03 from INC-001 to INC-003. Further presses do nothing; reload resets the session. IncidentStore owns current communications and resource intervention history. Dynamic route assignments replace previous journeys and discard stale routing responses. Pending incident cards sort by highest effective urgency, then oldest question; the log's pending queue is FIFO. Resolving one question must not clear an incident's other pending alerts.
- Question deadlines are absolute and use real seconds (critical/high/moderate: 60/120/300), never the routes' 10x clock. Closing the panel or leaving Home must not pause deadlines. Decisions are idempotent by question ID, preserve drafts until resolution, validate current assignments/status before effects, and record whether the answer was human or automatic.
- Future adapters can provide `OPERATION_LOG_UPDATES` (defaults to `EMPTY`) and consume `OperationLogStore.answers$`. The current executor only changes in-memory demo data. Production deadlines, persistence and cross-client idempotency belong to the backend.
